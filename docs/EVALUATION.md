# 记忆规则离线回放：SM-2 vs FSRS-4.5（2026-10-24）

> 目的：回答「要不要把现在的 SM-2 调度换成 FSRS」——不靠直觉，用同一套指标做回放对比。
> 脚本：[`scripts/replay-compare.ts`](../scripts/replay-compare.ts)
> 指标口径：[`REVIEW_RULES.md`](./REVIEW_RULES.md) §十一、`POST /api/review/metrics`

## 一、方法

- **两个调度器**：
  - `SM-2`：线上正在用的 `src/lib/scheduler.ts`（四档 + 间隔乘数 + 归档门槛）
  - `FSRS-4.5`：`src/lib/fsrs-lite.ts`（FSRS-4.5 默认 19 参数；目标保持率可配，默认 90%）
- **合成学习者**：80 张卡，真实初始稳定性中位数 2.5 天（对数正态，σ≈0.7）；答对后稳定性 ×1.7、答错 ×0.55 并设上下限
- **两种真实遗忘模型**（避免结论只对一种曲线成立）：
  - 指数：`R(t)=0.9^(t/S)`
  - FSRS 幂律：`R(t)=(1+19/81·t/S)^-0.5`
- **日程**：84 天，每天最多引入 3 张新卡、每天最多复习 20 张；到期按到期先后
- **可复现**：固定 seed（默认 42）、确定性 PRNG；同参数字节级一致（脚本自检）

```bash
./node_modules/.bin/tsx scripts/replay-compare.ts
# 可调：--days 84 --cards 80 --new-per-day 3 --daily-cap 20 --seed 42 --fsrs-retention 0.9
```

## 二、结果

|---|---|---|---|---|---|---|
| SM-2 | 450 | 5.36 | 92.2%（91.9%） | 86.8% | 82.9% | 1.3% |
| FSRS@90% | 358 | 4.26 | 86.3%（86.1%） | 78.9% | 73.6% | 3.8% |
| FSRS@95% | 499 | 5.94 | 94.2%（93.9%） | 92.5% | 87.2% | 0.0% |

### FSRS 幂律遗忘模型

| 调度器 | 复习次数 | 次/天 | 整体正确率（平滑） | 7–13 天 | 14+ 天 | leech |
|---|---|---|---|---|---|---|
| SM-2 | 401 | 4.77 | 95.3%（94.8%） | 91.5% | 92.2% | 0.0% |
| FSRS@90% | 339 | 4.04 | 88.2%（87.9%） | 83.6% | 77.5% | 3.8% |

## 三、怎么读这组数字

1. **FSRS@90% 不是「更差」**：它用**少 15–20% 的复习次数**换 **低 6–7pp 的保持率**。FSRS 的默认目标是 90% 保持率；SM-2 在合成数据里实际排得更密（约 92–95%），所以复习更多。
2. **把 FSRS 目标调到 95%**：保持率追平甚至略超 SM-2（+0.4~+2.0pp），代价是**复习次数多 11–20%**。
3. **没有免费午餐**：两种模型下，SM-2 都落在两个 FSRS 档位之间。差异的本质是「目标保持率 / 复习预算」的取舍，而不是算法谁绝对更好。
4. **合成数据不能替代真实数据**：这里的学习者是我们假设的，FSRS 的「90%」是按它自己的遗忘曲线算的；真实用户的遗忘曲线需要 `practice_events` 里积累的真实复习日志才能验证。

## 四、结论（当前决策）

- **线上调度暂不切换**，继续用 SM-2；`FSRS` 只作为评估候选保留在 `src/lib/fsrs-lite.ts`（不参与线上路径）。
- 真要切换时，必须满足：
  1. 真实复习日志 ≥ 每个用户 400 条（官方 FSRS 优化器也建议这个量级再用参数）；
  2. 用真实日志重跑本脚本（把 `practice` 从合成改成用户导出），比较「同复习次数下的保持率」与「同保持率下的复习次数」；
  3. 以**开关**方式引入、默认关闭，先小范围 A/B（按用户/按周轮换），保留状态迁移函数；
  4. 目标保持率必须可配（本回放显示 90% 和 95% 的结论完全不同）。
- **不要**用「正确率上升」单独判定改进：目标区间是 70–85%，保持率与复习预算是成对指标。

## 五、怎么用真实日志重跑

1. 用宿主（AI 助手）从用户的 `practice_events` 导出最近 N 条：`答题时间`、`是否正确`、`题型`、`复习间隔`（没有这个字段先补上）
2. 把本脚本的 `simulate()` 换成「顺序回放真实日志」：
   - 对每条真实作答，用对应调度器算出「如果按它的规则，下次该什么时候复习」
   - 对比预测的到期日与真实复习日，计算保持率 / 复习次数
3. 或者等数据够了以后，直接引入 [fsrs-optimizer](https://github.com/open-spaced-repetition/fsrs-optimizer) 在**宿主本地**拟合用户参数（数据不出用户的飞书表）
4. 把新结论更新回本文件与 `DECISIONS.md`

## 六、已知局限

- FSRS-4.5 是简化实现（learning steps 折叠到天粒度、不模拟同日多次复习）；用于相对比较，不代表 FSRS 官方实现的最佳效果
- 合成学习者假设「答对后稳定性固定 ×1.7」；真实增长与卡难度相关，FSRS 的难度参数正是为此设计
- 没有模拟提前复习、跳过一次练习、跨时区等行为；真实日志回放时应把这些过滤规则写清楚
