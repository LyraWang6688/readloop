# 复习与出题规则（确定性）

> 状态：草案，待评审后冻结
> 最近更新：2026-10-23
> 上位文档：[ARCHITECTURE.md](./ARCHITECTURE.md)
> 理论依据：[MEMORY_SCIENCE.md](./MEMORY_SCIENCE.md)（每条规则的出处与现存偏差）
> 命名：项目更名为 ReadLoop（仓库地址 `LyraWang6688/readloop`）

本文件定义**不依赖大模型**的那部分逻辑：答题档位、状态迁移、间隔计算、每日组题、幂等约束。

大模型只在两处出现，且都在离线侧：

1. 把知识点变成题面（每天早上批量生成一次，答题时零调用）
2. 把翻译对比诊断成知识点（采集时调用，不参与复习调度）

**模型本身是可配置项**，不绑死供应商：服务端环境变量指定 `LLM_PROVIDER` / `LLM_MODEL` / `LLM_API_KEY`，测试期统一用 **DeepSeek**；用户级覆盖接口预留，界面不做。换模型只影响题面措辞，**不影响选题与判分**（见 [ARCHITECTURE.md](./ARCHITECTURE.md) §5.5）。

---

## 一、设计原则

1. **选题是确定的**：同样的知识库状态，同样的一天，选出同一批题。
2. **判分是确定的**：选择题 / 填空题按标准答案判；不允许模型自行判断对错。
3. **回写是确定的**：状态迁移只有一套规则，不因宿主不同而不同。
4. **幂等**：同一天多次调用取题接口，必须返回同一套题；同一题重复提交不得重复计分。
5. **可单测**：`scheduler.ts` 是纯函数，输入 `(state, grade)` 输出新状态，不碰数据库。

参考实现（GitHub）：

- [ankitects/anki](https://github.com/ankitects/anki) —— 卡片状态机（new / learning / relearning / review / leech）
- [VienDinhCom/supermemo](https://github.com/VienDinhCom/supermemo) —— SM-2 的 TypeScript 实现
- [open-spaced-repetition/ts-fsrs](https://github.com/open-spaced-repetition/ts-fsrs) —— 后期替换 FSRS 时使用

## 二、知识点状态机

| 状态 | 含义 | 进入条件 |
|---|---|---|
| `new` | 刚入库，没练过 | 采集流程新建 |
| `learning` | 练过但未稳定（间隔 < 1 天） | 新点首次作答 / 答错后 |
| `review` | 稳定复习中（间隔 ≥ 1 天） | learning 毕业 |
| `relearning` | 复习时答错，掉回短期 | review 状态下答错 |
| `mastered` | 归档，不删除 | 债务归零 + 连对 ≥3 + **这次是在 ≥7 天间隔之后答对的** |

```text
new ──首次作答──▶ learning ──答对──▶ review
                    ▲                  │
                    │                  │答错
                    └── relearning ◀───┘
                                          │连对
                                          ▼
                                       review
review ──债务归零+连对≥3+跨过7天间隔──▶ mastered ──再次暴露──▶ new（重新激活）
```

`mastered` 是从活跃集合移出，不是删除。再次暴露（阅读中又错、或答错）时重新激活，练习债务重置。

**为什么要求「跨过 7 天间隔」**：如果只要求「连对 3 次」，第 3 次答对时系统刚把下次间隔排到 8 天，用户**还没真正等过 8 天再回忆**。要验证的是长间隔后的保持率，所以必须在 ≥7 天的间隔之后答对，才允许归档。

## 三、答题档位（四档，不是对/错）

| 档位 | 判定来源 | 说明 |
|---|---|---|
| `Again` | 答错 | 选择/填空判错；短翻译由规则引擎按关键词覆盖判定（第二批） |
| `Hard` | 答对但用过提示 / 超时 / 靠拼写容错通过 | 宿主上报的 `used_hint` / `elapsed_ms` |
| `Good` | 答对 | 选择题答对 |
| `Easy` | 答对且为生成式 | **填空题答对**（用户自己写出答案） |

### 题型只有两种，判分完全确定性

| 题型 | `type` | 交互 | 答对记 |
|---|---|---|---|
| 选择题 | `choice` | 从选项里选 | `Good` |
| **填空题** | `cloze` | **用户自己输入答案**，不给选项 | `Easy` |

**填空题必须是输入式，不能做成「给选项的填空」**——那本质仍是识别式，等于没有生成式练习。

判分实现见 [`src/lib/grading.ts`](../src/lib/grading.ts)，规则：

1. 归一化：去空白、合空格、小写、去包裹标点
2. 比较用 Damerau-Levenshtein（相邻字符对调算 1 次编辑）
3. 容错阈值按词长：≤4 字母不容错（`from`/`form` 是两个字），5–8 容 1，≥9 容 2
4. 容错通过记 `Hard`——答对了，但不干净
5. **全程不调用大模型**

实测：`scripts/grading-check.ts`（28 项断言）。

**信号强度**：`Easy` 高于 `Good`，且「真实阅读中再次遇到并自己译对」应记为 `Easy` 并额外加权（见 §七）。

## 四、间隔计算（SM-2 简化版）

初始值：`ease = 2.5`、`interval = 0`、`streak = 0`、`lapses = 0`、`need = 3`。

```text
Again:
    lapses   += 1
    streak    = 0
    need     += 1                 （上限 8）
    ease     -= 0.20              （下限 1.3）
    interval  = 0                 （当天重考，见 §五）
    next_review = 明天（且标记为必出）

Hard / Good / Easy:
    streak   += 1
    need     -= 1                 （下限 0）

    若 interval == 0（learning 阶段首次答对）：
        Hard / Good → interval = 1 天
        Easy        → interval = 4 天
    否则：
        Hard → interval = round(interval × 1.2)
        Good → interval = round(interval × ease)
        Easy → interval = round(interval × ease × 1.3)

    ease 调整：Hard −0.15 / Good 0 / Easy +0.15，夹在 [1.3, 2.8]
    next_review = 今天 + interval 天
```

**效果预期**：连续答对时，间隔按 `1 → 3 → 8 → 20 → 50` 天滚动（ease 保持 2.5 时；实测见 `scripts/scheduler-check.ts`）。
归档通常发生在第 4 次答对——那时已经跨过 8 天间隔，验证过长间隔后的保持率。

**难题（leech）**：`lapses >= 4` 时打标，不再按普通到期出题，改为每 7 天强制出现一次，并在题面提供提示（例句 / 首字母）。

## 五、与 Anki 的关键差异

Anki 面向「一次坐下来连续刷」的会话，learning step 以分钟计（1 分钟 → 10 分钟）。ReadLoop 是**每天推送一次**，分钟级调度没有意义。必须做的适配：

| Anki | ReadLoop |
|---|---|
| 答错后 1/10 分钟重考 | 若用户仍在当前会话，追加到本次队列末尾；否则次日必出 |
| leech 阈值 8 次 | 4 次 |
| 会话内不限量 | 每日固定题量（默认 8 题） |
| 用户主动打开 | 定时推送触发 |

## 六、每日组题

```text
今日题量 N = 8

① 到期复习   state ∈ {review, relearning} 且 next_review ≤ 今天
             排序：(逾期天数 desc, need desc)，最多 5 题
② 重学补考   昨日答错且标记必出的点，最多 2 题
③ 新点       state = new，按入库时间倒序，数量 = newQuota
④ 补位       仍不足 N 题时，从 need 最高的活跃点随机抽取

⑤ 动态难度   配额由 adaptDifficulty() 按最近 20 题真实正确率给出：
             正确率 > 85% → 加难（newQuota +1、leechQuota +1）
             正确率 < 70% → 降难（各 -1）
             70–85% 区间内 → 维持
             样本 < 10 题 → 不调整（几道题说明不了水平）
             实现：src/lib/difficulty.ts（20 项断言见 scripts/difficulty-check.ts）
⑥ 题型配比   选择 40% / **输入式填空 40%** / 短翻译 20%（短翻译在第二批启用）
             —— 输入式填空是生成式练习，判分确定性，不调用大模型
             —— 当前生成式占比 40%，后续加短翻译可到 60%
⑦ 打散       同类型题目不相邻；同一来源文章连续不超过 2 题
```

**MVP 实现口径**（2026-10-23，见 `docs/API_IMPLEMENTATION.md` §4 与 `docs/DECISIONS.md`）：

- 短翻译未启用 ⇒ 在「选择 / 输入式填空」两类内按 **1:1 交替**（等价于把 20% 摊进前两类），
  不足 3 个干扰项时该题强制为输入式填空
- 题面由**确定式模板**生成（掩码来源原句 / 释义提示），不调用大模型；LLM 润色默认关闭
  （`READLOOP_QUESTION_LLM=1` 才启用，失败回退模板）
- 难题（lapses ≥ 4）：不单独排除，但在到期/补位排序里靠前，题面给「首字母 + 字母数」提示；
  「每 7 天强制出现一次」需要 `practice_events` 历史，当前接口没传，MVP 暂不做（第二批补）
- 选题的确定性由 `(date, 知识点集合)` 派生的种子保证：同样的输入与日期 ⇒ 同一批知识点与同一题型分配

「随机」只出现在 ③④ 的池内抽样与 ⑦ 的排序，**规则本身完全确定**。

**为什么难度要动态**：合意困难是「按人」的——同一个配比对 A 太简单、对 B 太难。
静态配额只能保证「不太离谱」，动态配额才能让每个人落在各自的 70–85%。

参考文档对练习形式的取舍：检索练习优先于重复阅读、交错练习优先于同类连刷、语境化优先于孤立记忆、生成式优先于识别式、难度控制在「努力后能答出来」的区间。

## 七、信号加权

| 信号 | 来源 | 对状态的影响 |
|---|---|---|
| 做题答对 | 宿主答题 | 标准流程 |
| 做题答错 | 宿主答题 | 标准流程 + 次日必出 |
| 真实阅读中再次遇到并自己译对 | 插件采集 | 视为更强信号：`need −2`、`streak +2`，可直接推动归档 |
| 真实阅读中再次遇到但仍未译对 | 插件采集 | `need +1`，重置 `streak` |

第三条是本产品区别于普通背单词工具的核心信号，也是唯一只能由插件采集的信号。

## 八、幂等与一致性

1. **取题幂等**：服务端无状态，同一 `(date, points)` 用确定性种子选出同一批题；
   `daily_sets` 缓存由宿主写进用户自己的表（可选表），服务端不存
2. **提交幂等**：`question_id` 签名里带**作答前的状态快照**，重复提交同一题返回同一组 `updates`，
   不重复计分；客户端无法伪造或篡改快照（见 `docs/API_IMPLEMENTATION.md` §2.3）
3. **采集去重**：按 `(user_id, type, normalized_content)` 先查后写。命中则 `encounter_count + 1`、`need + 1`；未命中才新建。
4. **并发**：多维表格无事务，MVP 单人使用可接受；多用户前必须切换到支持事务的存储。

## 十、边界情况

| 场景 | 处理 |
|---|---|
| 新用户，知识库为空 | 返回空今日包，宿主提示「先去读一篇文章」 |
| 到期积压超过 20 题 | 只取最紧急的 5 题，其余自然顺延，不增加每日题量 |
| 同一天多次打开 | `daily_sets` 命中，返回同一套题与已答进度 |
| 连续 3 天未作答 | 不重置状态，仅顺延；第 4 天恢复正常 |
| 全部知识点已归档 | 提示「当前没有待复习内容」，并推荐新文章 |
| 某题被反复答错 4 次以上 | 标记 leech，降低频率并给提示 |
