## 一、三本书

**1.《认知天性》（Make It Stick）** — Brown / Roediger / McDaniel

这个产品的理论说明书。四条核心结论正好是我们四条规则：

- 检索练习 > 反复阅读（考试效应）
- 间隔 > 集中
- 交错 > 同类连刷
- 合意困难：学得「费劲」才记得住

**2.《我们如何学习》（How We Learn）** — Benedict Carey

讲遗忘曲线、睡眠巩固、环境变化对记忆的影响。比第一本通俗，回答「为什么」。

**3.《与爱因斯坦月球漫步》（Moonwalking with Einstein）** — Joshua Foer

记忆术（记忆宫殿、联想编码）。**我们不让用户背记忆术**，但可以借鉴它的核心：把抽象信息挂到具体场景上——这就是「来源原句」的理论依据。

## 二、四个核心方法论

| 方法论 | 一句话 | 我们的落地 |
|---|---|---|
| **间隔重复**（Spaced Repetition） | 在快忘的时候复习 | [scheduler.ts](../src/lib/scheduler.ts) 的间隔曲线 |
| **检索练习**（Retrieval Practice） | 让用户「想起来」，不是「再看一遍」 | 生成式题优先于选择题 |
| **交错练习**（Interleaving） | 换着类型考，别连着刷同一种 | 每日组题的题型打散 |
| **合意困难**（Desirable Difficulty） | 难度控制在「努力一下能答对」 | 目标成功率 70–85% |

### Bjork 的「双强度」——解释我们为什么要逼用户自己译

Bjork 把记忆分成两种强度：

```
反复看   → 提取强度高、存储强度低   （看着眼熟，用不出来）
努力回忆 → 提取强度低、存储强度高   （当时费劲，但记得牢）
```

这就是「**先自己翻译，再给参考译文**」这条产品原则的科学依据：

- 直接给译文 = 反复看 → 用户觉得「懂了」，但下次读还卡
- 逼自己译 = 努力回忆 → 卡一下，然后记住

同理，选择题只提供「认出来」的机会，**输入式作答才提供「想起来」的机会**。

## 五、现有实现的三个偏差（诚实记录）

### ① 检索练习没落地 —— ✅ 已修正（2026-10-23）

原来 MVP 的「填空题」是**给选项的填空**，本质仍是识别式，等于一条生成式都没有。

**已改为「用户自己输入」**，判分用规范化匹配 + Damerau-Levenshtein 容错：

- 用户必须自己写出答案 → 生成效应成立
- 判分完全确定性，**不调用大模型**
- 生成式占比从 0% 提升到 40%（短翻译启用后到 60%）

实现：[`src/lib/grading.ts`](../src/lib/grading.ts)，实测 [`scripts/grading-check.ts`](../scripts/grading-check.ts)（28 项断言全过）。

### ② 合意困难没有闭环 —— ✅ 已修正（2026-10-23）

原来只有「新点 ≤25%、难题 ≤20%」的**静态配额**，而 70–85% 是按人的——同一配比对 A 太简单、对 B 太难。

**已实现 `adaptDifficulty()`**（[`src/lib/difficulty.ts`](../src/lib/difficulty.ts)）：

| 最近 20 题正确率 | 动作 |
|---|---|
| > 85% | 加难：新点 +1、难题 +1 |
| 70–85% | 维持 |
| < 70% | 降难：各 −1 |
| 样本 < 10 题 | 不调整（几道题说明不了水平） |

数据来自 `practice_events`，实测 20 项断言（[`scripts/difficulty-check.ts`](../scripts/difficulty-check.ts)）。

### ③ 归档太快 —— ✅ 已修正（2026-10-23）

原规则「债务归零 + 连对 3 次」就归档，问题在于：第 3 次答对时系统刚把下次间隔排到 8 天，**用户还没真正等过 8 天再回忆**。

**已改为「必须是在 ≥7 天间隔之后答对」**：

- 归档通常发生在第 4 次答对（约两周后）
- 验证的才是长间隔后的保持率，而不是短间隔刷够次数

实测见 [`scripts/scheduler-check.ts`](../scripts/scheduler-check.ts) 第 7 组。

## 六、待验证的假设：推送时间

睡眠对记忆巩固有明确作用，**睡前学习 + 睡一觉，保留率通常高于白天学完就干活**。

对应 `schedule` 的两个默认选项：

| 时间 | 可能的优势 |
|---|---|
| 21:00 | 记得更牢（睡眠巩固） |
| 09:00 | 更容易养成习惯（固定动作） |

两个目标冲突，**不拍脑袋**：给两批用户各配一种，看 7 天后留存与正确率。这也是「推送时间」作为配置项的价值。

## 七、这为什么是护城河

规则本身可以被抄，但这两样不容易：

1. **有理论依据的规则体系**——不是拍脑袋定的参数，每条都能追到出处；
2. **用真实数据持续校准**——`practice_events` 累积后可以验证「归档门槛是否太快」「难度是否真在 70–85%」，别家没有你的数据。

所以对外的说法可以是：

> 不是又一个背单词 App，而是一套**有记忆科学依据、并由你的真实阅读数据持续校准**的复习机制。

这也是后端服务必须存在的理由：**规则和校准逻辑在我们手里，不在包里**。
