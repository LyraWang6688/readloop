## 一句话定位

> **ReadLoop：读的时候暴露短板，AI 助手按时帮你复习。**

ReadLoop 是一个围绕真实兴趣阅读展开的英语能力迭代系统。

它不是传统英语学习 App，也不是直接帮用户读完文章的翻译工具。它让用户在阅读自己真正关心的英文内容时暴露理解短板，把短板沉淀为个人知识库，再通过科学练习机制持续修复这些短板。

## 目标用户

用户已经有一定英语基础，能阅读基础英文内容，但因为长期缺少练习，在阅读 AI、产品、商业、创业、科技等英文文章时会出现生疏、漏译、理解偏差或表达不准。

他们的核心动机不是从零学英语，也不是按课程从易到难训练，而是希望逐渐更顺畅地阅读自己关心领域里的英文内容。

## 核心闭环

```text
真实兴趣阅读
  -> 用户尝试翻译/理解段落
  -> AI 对比用户翻译与参考翻译
  -> 识别用户真实暴露的不足
  -> 生成并沉淀知识点
  -> 知识库按记忆规律调度练习
  -> 后续阅读同类文章更顺畅
```

## 功能原则

1. 阅读材料来自用户真实兴趣，而不是系统安排的课程材料。
2. 知识点只应来自用户在翻译对比中暴露的问题，不做泛化式词库扩张。
3. 知识库不是给用户浏览的笔记本，而是系统用于调度、分析和掌握判断的动态状态库。
4. 练习不是为了刷题，而是为了减少后续阅读同类文章时的阻力。
5. 真正的掌握信号不只来自做题答对，也来自后续真实阅读中能正确理解同一类表达。

## 当前主链路

1. 用户通过 URL、粘贴文本或上传文件导入英文文章。
2. 系统解析文章并拆分成段落。
3. 用户选择段落并提交自己的中文翻译。
4. AI 生成参考翻译，并分析用户翻译中理解正确、表达可优化、遗漏要点的部分。
5. AI 从表达可优化和遗漏要点中提取知识点。
6. 用户点击“添加知识点到知识库”后，知识点写入 PostgreSQL。
7. 相同知识点再次出现时不重复新增，而是增加暴露次数和练习需求。

## 知识库定位

知识库是系统后台的“问题账本 + 练习调度器”，不是静态收藏夹。

每个知识点需要维护：

1. 它是什么：类型、内容、含义、解释、来源语境。
2. 它出现过几次：`encounter_count`。
3. 它还需要练多少：`practice_need`。
4. 用户是否连续掌握：`correct_streak`。
5. 什么时候再练：`next_review_at`。
6. 当前是否仍活跃：`is_active`。
7. 为什么变成当前状态：事件记录。

知识点生命周期：

```text
首次暴露 -> 入库
重复暴露 -> 增加练习需求
做题答对 -> 降低练习需求
真实阅读中掌握 -> 更强地降低练习需求
达到掌握阈值 -> 从活跃集合归档
未来再次出错 -> 重新激活
```

## 科学练习方向

每日练习不应随机出题，而应由知识库调度：

1. 新错题复现：最近新暴露的问题，趁遗忘前第一次强化。
2. 到期复习：根据 `next_review_at` 做间隔重复。
3. 真实阅读迁移题：回到历史原句或相似语境中验证理解迁移。

题量保持轻量，优先每天 5 到 10 题。重点是持续检索，而不是一次集中刷题。

## 与现有英语 App 的差异

两个差异点，且都**必须建立在数据连续性上**，否则不成立。

### 1. 生词来自你正在读的东西，不是预设词表

| 普通单词 App | ReadLoop |
|---|---|
| 词库预设（四六级 / 雅思 / 高频词），所有人学同一套 | 知识点由**你的真实阅读**暴露 |
| 关注 AI 也学同一批通用词 | 关注 AI，知识点就全是 AI 语境里的表达 |
| 例句是编的 | 例句就是**你读到的那句原文**，带来源链接 |

**关键约束**：复习题必须回到 `来源原句` 的语境里，否则会退化成普通单词卡，这个差异立刻消失。

**已知风险**：领域漂移（从 AI 转到金融）时，旧知识点会沉淀成噪音。靠「活跃 / 归档」机制处理，但领域视角需要单独想。

### 2. 陪伴式助手，而不是答题机器

| 普通 App | ReadLoop |
|---|---|
| 固定题型、固定反馈文案 | 宿主 agent 用对话陪着走：讲为什么错、追问、按连续表现调整语气 |
| 关掉就断 | 每天都在，且**记得你上次错在哪** |

**关键前提：陪伴感来自「它记得你」。** 记得你上周反复卡在哪个表达、这次是新错还是老错——这份记忆来自多维表格里的历史，不是模型的临场发挥。

所以：

```
陪伴 = 数据连续性 + 对话表达
```

只有后者，就是普通 chat，任何一个通用助手都能做，不足以构成产品。

### 边界依然成立

| 交给 agent | 必须由工具决定 |
|---|---|
| 语气、追问、鼓励、讲解方式 | 对错判定 |
| 用哪种界面呈现 | 下次复习时间 |
| 每日总结的表达 | 状态与练习债务的变更 |

两者不冲突：**agent 负责「怎么陪你」，工具负责「记得准」。** 陪伴是体验层，确定性是数据层。

## 当前技术路线

已被 2026-10-23 的架构调整取代，以 [ARCHITECTURE.md](./ARCHITECTURE.md) 为准：

1. 交付形态：**Skill 包**（浏览器插件 + 多维表格 + AI 宿主），不是 Web App。
2. 数据：用户自己的飞书多维表格，我们不托管。
3. 模型：用户自带（BYOK），默认推荐 DeepSeek。
4. 宿主：豆包工作 / Codex / Work Buddy（PC 桌面版）。
5. 触发：宿主定时任务，不自建 cron。
6. 不再使用 PostgreSQL / Drizzle / `coze-coding-dev-sdk` 作为主链路。

## 不再作为当前方向的能力

以下内容如果在旧文档中出现，应视为历史方案或低优先级参考：

1. 段落难度评估和推荐练习机制。
2. 从易到难的课程化学习路径。
3. 旧表格化方案作为主知识库存储。
4. IndexedDB 作为正式知识库主存储。
5. 以人工浏览知识库为核心的笔记式体验。
6. **以 Web App 作为主入口**（现改为插件 + 宿主）。
